# Changelog

## Unreleased

- [SECURITY] No model- or transcript-derived field reaches a tracker with a live mention or cross-reference in it any more, with the one exception named below. A tracker's title and summary, a Jira description and a GitHub issue body are all shown to other people — GitHub autolinks mentions in a title and in a body, and notifies on mentions in the body, resolves `#123` cross-references there too, and a tracker can show the same text again in notifications and activity feeds — so anyone who only controls what is on the recorded screen could have had the user's export ping arbitrary accounts in their repository, or forge a cross-reference to an unrelated issue. Every untrusted field that can carry a live trigger is now neutralized on the way out (a zero-width space after `@`, `#` and `GH-`, which leaves the text visually identical — including when a combining mark or a variation selector hides the trigger inside a character cluster), the Windows session title included, and the one field that is not neutralized — the deduplication hint in the GitHub body — is rendered inside a code span that markdown shows inert, and can no longer break out of that span. The GitHub body escapes its markdown too, and it now escapes inside a character cluster as well: a `[` that is part of a larger cluster opened a live link or image label, because a literal search matches whole character clusters and never reached it. Both ports work on code units there now, so they send the same body as well as the same title. The neutralization runs before the length cap, and the cap counts UTF-16 code units the way the trackers count them, so the field the tracker receives fits GitHub's 256 and Jira's 255 characters even when the title is dense in astral-plane characters; both ports now collapse and cut a title the same way, so they send the same title.
