# Changelog

## Unreleased

- [SECURITY] No model- or transcript-derived field reaches a tracker with a live mention or cross-reference in it any more, with the two exceptions named below. A tracker's title and summary, a Jira description and a GitHub issue body are all shown to other people — GitHub autolinks mentions in a title and in a body, and notifies on mentions in the body, resolves `#123` cross-references there too, and a tracker can show the same text again in notifications and activity feeds — so anyone who only controls what is on the recorded screen could have had the user's export ping arbitrary accounts in their repository, or forge a cross-reference to an unrelated issue. Every untrusted field that can carry a live trigger is now neutralized on the way out (a zero-width space after `@`, `#` and `GH-`, which leaves the text visually identical — including when a combining mark or a variation selector hides the trigger inside a character cluster), the Windows session title included. The first exception is the deduplication hint in the GitHub body: it is not neutralized, but it is rendered inside a code span that markdown shows inert, and it can no longer break out of that span. The second is the cross-reference the deduplication policy itself wrote — the matched issue the tracker context links to — which is restored after the neutralization; it is anchored to a fixed prefix, carries digits only, and the remote title and the model's reasoning around it stay neutralized. The GitHub body escapes its markdown too, and it now escapes inside a character cluster as well: a `[` that is part of a larger cluster opened a live link or image label, and a backtick that is part of one closed the deduplication hint's code span early, because a literal search matches whole character clusters and never reached them. Both ports work on code units there now, so the neutralizer produces the same output on both; the exported bodies still differ in structure, as they did before. The neutralization runs before the length cap, and the cap counts UTF-16 code units — how Jira counts its characters, and never more permissive than counting code points — so the field the tracker receives fits GitHub's 256 and Jira's 255 characters even when the title is dense in astral-plane characters; both ports now collapse and cut a title the same way, so they send the same title.
- [SECURITY] The local transcription server now accepts only the model it was configured to load. The model id in a transcription request used to pass through to the model loader, where it is either a Hugging Face repository or a local directory — the loader turns any download error into a local path — so a caller holding the bearer token could make the server read local files and load weights from a repository of its own choosing, at a revision that is not pinned to a digest.
- [FIX] A decode that hangs no longer takes the local transcription provider down with it. ffmpeg is given one window of the recording, so it cannot legitimately take longer than the window is long, but it ran without a timeout: a wedged ffmpeg held the single inference worker for ever, every later transcription waited behind it, and the window it was writing was never removed. The decode now has a timeout, and the partial window is removed.
- [SECURITY] The health check no longer hands a local path to every account on the machine. The route answers the app's proof challenge without a token, so any local user can read its answer, and the model-load failure it reported carried the absolute path of the managed models directory — a home directory on macOS and a %LocalAppData% profile path on Windows. The answer now carries one of the server's own fixed messages and none of the loader's text, and only the model ids the server knows are published as the model name: a model that lives in a local directory is published as a placeholder rather than as its path. The full detail stays in the server's own log.
- [INTERNAL] The local transcription notes claimed that every route requires the bearer token, including the health check. The proof challenge is the one exception: the app sends a nonce and accepts the answer only when the server returns the proof that only a holder of the token can produce. The architecture notes, the README, the user guide, and the comments in the macOS app, the Windows port, the server and the smoke tests now say so.
- [FIX] A refused local transcription request now carries a readable reason. A request without the bearer token, a request with a token the server does not accept, an upload over the ceiling, a body it cannot read, a request that is not the upload it expects, an unknown route and a method the route does not accept all answered with a bare `detail` field, and both shipped clients read `error.message` and fall back to a status-derived message when they cannot find one, so those refusals came back with no reason at all. Every refusal the server sends now answers with `error.message` and `error.type`.
- [FIX] A model id the server refuses no longer takes the server down with a traceback. A refused `--model` is the operator's own argument rather than a runtime failure, so the server now names what was wrong and stops.
- [FIX] The local transcription failure message no longer points at a log file the user cannot open. It told the user to check the local transcription server logs, but the server writes to its own output — `server.stderr.log` in the install directory on Windows, the terminal when the user started the server by hand — so it now says the details are in the local transcription server's output. On macOS the app drains that output and does not keep it as a file, so the pointer is weaker there than it is on Windows.
- [FIX] Explain how to stop a leftover local transcription helper in Activity Monitor when a server update cannot retire it safely.
