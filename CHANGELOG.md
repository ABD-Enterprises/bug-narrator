# Changelog

## Unreleased

- [SECURITY] The validation gate's Semgrep scan is pinned. The image ran from a mutable tag and the rules were fetched from the registry at run time, so an upstream tag move or a registry compromise changed what ran in CI, and two scans of the same commit did not look for the same things — the registry's rule set changed between two downloads minutes apart while this was being fixed. The image is now addressed by digest and the rule set is vendored in the repository (`semgrep/semgrep-auto.yaml`), refreshed deliberately with `scripts/update-semgrep-rules.sh`; `scripts/check-semgrep-pinning.sh` proves the pin is still in place and runs as part of the gate. The Semgrep token no longer has to be handed to the container at all. The vendored rule set is the registry's minus the 44 secret-detection rules under `generic.secrets.`, whose example values are shaped like real credentials and which GitHub's push protection refuses in a push; this repository already has GitHub's secret scanning, so the rules are left out rather than worked around. The file's header says what is missing and why.
- [SECURITY] `scripts/validate.sh` now fails closed when it cannot diff against the base ref. The changed-file list comes from `scripts/changed-files.sh`, where git's exit status is no longer discarded by a process substitution, so a stale, missing or unrelated base ref can no longer produce a green Semgrep PASS while the scanner looked at no files; the shell and Python lint listings are captured with the same explicit error check. The helper falls back to a direct tree comparison when a shallow checkout has no merge base, so the gate keeps working in CI's shallow clones, and it keeps non-ASCII paths scannable. `scripts/check-changed-files.sh` pins the behaviour — the gate itself, not just the helper — and runs as part of the gate.
- [INTERNAL] The update-check parity matrix documents Windows-specific package selection and search limits instead of incorrectly claiming both ports still use the same latest-release endpoint.
- [FIX] Windows update checks search published releases for an uploaded app package matching the running x64 or ARM64 process, ignoring macOS and transcription-server releases, drafts and prereleases. Windows tester tags compare correctly; links stay on this repository, and missing packages or incomplete searches report an unknown result rather than claiming the app is up to date.
- [SECURITY] Windows encrypts saved session metadata, transcripts, review summaries and recording drafts using AES-GCM with per-file keys wrapped by current-user DPAPI. Legacy plaintext/BOM sessions remain readable and upgrade on save, including retained draft notes; explicit exports remain plaintext. Encryption failures do not fall back to plaintext writes.
- [FIX] Windows Jira exports preserve configured context paths, with or without a trailing slash, in both issue-creation requests and returned issue links.
- [FIX] Windows issue review now previews screenshot highlights and lets reviewers reposition them by dragging or keyboard arrows and remove them before saving or exporting. Edits preserve annotation metadata and stay inside the image bounds; missing images retain their annotations and offer named removal controls. Session bundles render the current annotations instead of copying stale cached highlights.
- [INTERNAL] Adds `docs/reviews/2026-10-29-critical-review.md`, a point-in-time audit of the repository (Swift app, Windows port, local transcription server, CI and release automation): 6 P1, 8 P2 and 11 P3 findings, each with file-level evidence, impact and a specific fix, plus the areas that were checked and found sound. It is a work queue for follow-up, not a product document; identifiers that `AGENTS.md` keeps out of public files are redacted. Three findings are recorded as already fixed by later work: the Windows at-rest encryption gap (#1249), the Windows Jira context path (#1245) and, in part, the local transcription upload bound (#1239).
- [INTERNAL] Corrects a citation error in the review: the P2-2 regression tests for the Windows Jira context-path fix live in `windows/tests/BugNarrator.Windows.Tests/IssueExportProviderTests.cs`, not under an `Export/` subdirectory, and the P2 tally now reads one fixed, one partly fixed and six open.
- [FIX] Windows recording controls show saved recordings that still need transcription, offer Retry Transcription and Open Settings, and restore recovery after reopening the controls. Retry uses the same saved-session service as the library and refuses duplicate requests for the same session.
- [FIX] Local transcription bounds its memory on long recordings (#1229): uploads are streamed to disk in 1 MB pieces instead of read whole, each backend decodes one 120 s window at a time (ffmpeg seek windows on macOS, windowed WAV reads elsewhere), and the MLX Metal cache is released after every window and when a job finishes or fails, so peak resident memory no longer grows with recording length.
- [INTERNAL] Agent files follow the fleet standard: `AGENTS.md` is the single copy of the agent rules, `CLAUDE.md` only imports it and `.agent/rules.md` points at it; `scripts/check-agent-rules-sync.sh` now checks that layout instead of identical bodies, and the old ORC adapter text is gone.
- [SECURITY] The local transcription server's hash-locked builds (standalone, Windows x64 and Windows ARM64) move `certifi` from 2026.7.22 to 2026.10.19, which drops the emSign root CAs whose intermediate CA keys were compromised (GHSA-6q48-6c7w-9gw2, CWE-295, critical); no other pin changes.
- [SECURITY] The docs site (`/site`) dependency tree is updated to patched versions of `proxy-addr`, `shell-quote`, `compression`, `webpack-dev-middleware`, `http-cache-semantics`, `postcss-selector-parser`, `serialize-javascript`, `sirv` and `source-map-js`; `npm audit` for the site drops from 47 to 29 vulnerabilities (the rest need a Docusaurus migration or have no upstream fix).
- [SECURITY] The docs site (`/site`) now resolves `tinypool` 2.2.0 (root npm override; was 1.1.1, which carries a critical advisory); its only call site is Docusaurus's SSG worker pool behind `future.faster.ssgWorkerThreads`, which the site does not enable, and the site build is unchanged.
- [FIX] Audio recording: guarantee probe cleanup and reset active recording state on failed start, stop, or cancel to prevent temporary file leaks and zombie session locks.
- [SECURITY] The docs site (`/site`) no longer ships a vulnerable `brace-expansion`: a stale npm override pinned 1.1.18, which three newer advisories (high) affect; it now pins 1.1.21, and `fast-uri` moves to 3.1.8. `npm audit` for the site reports 0 vulnerabilities.
- [INTERNAL] Removed the unused Gemini Code Assist GitHub App configuration files.
- [INTERNAL] Removed the empty Terraform placeholder directory (no resources, providers or modules) and the docs and `.gitignore` entries that referred to it.
- [INTERNAL] Dependabot now also covers npm (`/site`) and pip (`/local-transcription`), monthly and grouped with a 7-day cooldown and semver-major held for review.
- A long recording with a silent stretch now transcribes: an empty chunk is skipped instead of failing the whole transcription (and every retry).
- Windows: recordings longer than about 13 minutes now transcribe — the WAV is uploaded in 8-minute chunks instead of failing at the provider's 25 MB limit after the upload.
- Windows: an issue whose primary field is null but carries an alias (e.g. `"title": null, "issueTitle": …`) or whose primary field is the wrong kind (`"confidence": "high"` beside `"score"`) is now read like macOS reads it, instead of failing the whole extraction or losing the field.
- Windows: untrusted text in exported GitHub issues can no longer render masked links, images, indented headings or forged list items (the macOS hardening, ported), and issue titles are normalised to one line and capped at Jira (255) / GitHub (256) limits before export.
- Windows session summaries no longer cut the lead sentence at a decimal point or a dot inside a word ("Version 1.2 crashed" summarised as "Version 1.").
- Windows: a model reply carrying a non-finite timestamp or confidence ("NaN", "1e999") no longer crashes the session library; such values are treated as absent, and time labels render 0:00 for any non-finite value already saved.
- Windows screenshot geometry can map a selection piecewise into each monitor's native pixels (groundwork for per-monitor DPI capture; behaviour unchanged until the PerMonitorV2 switch in #1192).
